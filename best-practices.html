📋 Prompt Library Copy, adapt, and use — add your own after the interview program
How to use this library: These are starting points, not scripts. Always add your specific context — product area, user type, constraints. The best prompts are the ones you adapt to your situation.
Research Synthesis — Multi-Source Themes Research
I have [X] sources of user research: [list: interview notes, Jira tickets, Confluence pages, survey data, support tickets]. Analyze all of them and: 1. Identify the top 5 recurring themes across all sources 2. For each theme, provide 2–3 direct evidence quotes 3. Flag any contradictions or gaps between sources 4. Suggest 3 open questions that still need answers Output as a structured document with clear section headers.
📍 Based on Yaara Bar Feldman's workflow Best for: research synthesis, cross-source analysis
Developer Handoff — Component Spec Handoff
Generate a structured developer handoff spec for the following UI component: Component: [name] Purpose: [what it does, user goal] Variants: [list variants] States: [default, hover, active, disabled, loading, error, empty] Interactions: [describe behaviors] Content rules: [character limits, placeholder text, validation rules] Accessibility: [ARIA labels, keyboard behavior, focus order] Edge cases: [what can go wrong, how to handle it] Output as a clean Markdown document (.md) that a developer can work from without needing to ask follow-up questions.
📍 Based on Tali Silon-Shacham's workflow Best for: dev handoff, spec documentation
Design Ideation — Divergent Directions Ideation
I'm designing a solution for the following: User goal: [what the user is trying to accomplish] Business constraint: [key limitation or requirement] Context: [product area, user type, platform] Generate 6 distinct design directions. Each should be genuinely different — not just variations of the same approach. For each direction include: - Core concept (1 sentence) - What makes it different - Main tradeoff or risk - What type of user it works best for Do not default to the obvious solution first.
📍 Inspired by Gajanan Rajput's ideation workflow Best for: early exploration, avoiding groupthink
UX Writing — Microcopy for UI States UX Writing
Write microcopy for the following UI states: Component: [name] Product tone: [e.g., professional, direct, reassuring] User context: [what the user just did / is trying to do] Write copy for: - Default label / placeholder - Success state - Error state (what went wrong + how to fix it) - Empty state (no data yet) - Loading state Keep it under [X] characters per state. Avoid generic phrases like "Something went wrong." Be specific to what the user is doing.
📍 General — community contributed Best for: microcopy, UI text, all states

✅ Do's & Don'ts Based on survey data + Champion experience
✅ Do
⚡Use AI for the production work — spec writing, synthesis, annotation, microcopy. These are the highest-ROI tasks.
📖Always read raw transcripts yourself. AI finds patterns — you find meaning. Never skip the human validation step.
✏️Treat AI output as a first draft. 65% of outputs need minor edits, 35% need significant rework. Budget time for review.
🔄Use multiple tools to validate each other. One AI's output checked by another catches errors neither would catch alone.
📤Share what works. If a prompt saved you 2 hours, add it to the library. Zero people currently share nothing — let's keep it that way.
🎯Give AI specific context. The more specific the prompt (product, user type, constraint), the less rework you'll need.
❌ Don't
🚫Don't use AI output as-is. 0% of the team does — and that's right. Always review before sharing externally.
🚫Don't let Dev or PM use AI to build UI before UX is involved. AI-generated UI without UX input creates irreversible design debt.
🚫Don't paste confidential customer data into public AI tools without checking the company AI data policy first.
🚫Don't use AI to skip the thinking. Use it to compress production time. Judgment, prioritization, and decision-making stay human.
🚫Don't work in isolation. The biggest waste right now is everyone discovering the same things independently. Use the shared library.
🚫Don't ignore quality just because it was fast. Speed and quality aren't opposites — but AI can make it easy to miss problems at scale.
"AI eliminated production time. Thinking time stayed the same. What didn't compress: running sessions, prioritizing recommendations, reading transcripts yourself, making judgment calls." — Yaara Bar Feldman
